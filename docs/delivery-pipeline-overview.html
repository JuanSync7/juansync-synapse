Delivery Pipeline — Customer → Green Build

Full working principle: actor model, stage flow, protocol injection, artifact map, resumability.

1. Actor model

Three contexts, three altitudes. Protocols are not actors — they are system-prompt fragments injected into whichever context needs that discipline.

ContextLivesOwnsScope
Customer Outside the system The goal, gate decisions Approves / redirects at each handoff
Main agent Top-level conversation, multi-turn, durable across compaction Orchestration, all writer skills, plan-writer, plan-executor outer loop, filesystem audit trail Stateful — owns INDEX.md, STORIES.md, closeouts/, lessons.md, CHANGELOG.md
Subagent One-shot dispatch from main, exits at closeout Inner TDD/Ralph loop for one slice Stateless across slices — fresh context per dispatch

2. Stage flow (vertical-slice pipeline)

Skill: delivery-program-program-orchestrator (proposed, top of stack)

Stage 0 — Intake + shape detection

Customer drops PRD / spec / chat-intent goal. Orchestrator classifies the request as vertical-slice or horizontal/per-module work and decides which upstream stages to skip vs. require.

  • Vague intent → routes to Stage 1 discovery
  • PRD present → skips to Stage 2
  • Spec + arch + scope already on disk → skips to Stage 5
▼
Inline interview node (orchestrator or plan-writer [Q])

Stage 1 — Discovery / clarification

3–5 targeted questions until the minimum chat-intent schema is filled: problem, in-scope, out-of-scope, constraints.

GATE — customer confirms the framing.
▼
Skill: /docs-spec-writer

Stage 2 — Spec authoring

Produces SPEC.md — FR-NNN list, NFRs, glossary, actors, acceptance criteria.

GATE — customer reviews SPEC.md, approves or revises.
▼
Skill: /docs-architecture-writer

Stage 3 — Architecture

Produces architecture.md — tech stack, component boundaries, data flow, integration approach.

Load-bearing: foundations: [auth, db, logger] frontmatter field. Plan-writer's [F] foundation cascade reads this structurally — do not omit.

GATE — customer signs off on tech stack.
▼
Skill: /docs-scope-writer

Stage 4 — Scope / phasing

Produces scope.md — Phase 1 (TAG=AUTH), Phase 2 (TAG=BILL), and so on. Each phase corresponds to one plan-writer run.

GATE — customer picks the TAG to plan now.
▼
Skill: /delivery-plan-writer --tag AUTH

Stage 5 — Vertical-slice planning

Flow: [NEW] → [START] → [H] → [F] → [D] → [M] → [END]

  • [START] pre-flight — tag, input-mode, writable directory
  • [H] horizontal doc discovery — reads architecture.md / NFRs / scope; surfaces CONFLICT blocks rather than silently resolving
  • [F] foundation cascade — declared → architecture foundations: → ≥60% cross-FR heuristic → none-with-risk; records foundation_source in STORIES.md
  • [D] decompose — 4-required + 6-extension frontmatter; granularity gates (HARD floor, SOFT cap = 8 files, ≤30 stories, no 1-story decomposition); topo-sort + cycle detect
  • [M] manifest assembly — STORIES.md + atomic batch write of all story files

Output: .delivery/stories/AUTH-NNN-*.md + STORIES.md (frontmatter: tag, spec_hash, foundation_source).

GATE — customer reviews STORIES.md graph, approves.
▼
Skill: /delivery-orchestration-plan-executor

Stage 6 — Plan execution — Ralph outer loop

Flow: [PRE-FLIGHT] → [PICK-NEXT-SLICE] → [DISPATCH] → [INGEST] → [REPLAN] → …

Per-slice (sequential by default):

  • [DISPATCH] builds the subagent system prompt — slice body + 3 worker-side protocols injected via {{worker_protocols}} slot + per-story discipline_deltas
  • Subagent runs inner Ralph/TDD loop: red → green → refactor up to iteration cap (default 10); emits closeout YAML via dual-target atomic write
  • [INGEST] reads closeout, updates INDEX.md status
  • [REPLAN] per replan-contract: green → next slice; blocked → replan or escalate; plan_drift_detected → re-shape stories; M=3 replan cap → escalate

Termination conditions: all_slices_green | escalated_blocked | escalated_replan_cap | user_interrupt

▼
Format: references/final-summary-format.md

Stage 7 — Termination + handoff summary

Surfaces exit reason, slice rollup, slice detail, lessons tail (5–10 verbatim), pointers (INDEX.md, closeouts/, lessons.md, CHANGELOG.md), and a single-sentence next move mapped from the exit reason.

GATE — customer decides merge / escalate / re-shape.

3. Protocol injection map

Which protocol enters which context, at which stage, why.

ProtocolInjected intoStageWhy
delivery-execution-slice-contract Subagent system prompt (also read by plan-writer at [D] for emit-format) 5 [D], 6 [DISPATCH] Defines a slice — required fields, size bounds, violation signatures. Plan-writer emits to it; worker is measured by it.
delivery-execution-tdd-contract Subagent system prompt 6 [DISPATCH] Inner Ralph/TDD loop discipline — test-first, iterate-to-green, cap-aware-blocked.
delivery-execution-coding-contract Subagent system prompt 6 [DISPATCH] Code-quality discipline — YAGNI, neighbors-first, no-dead-code, fail-loudly, green-tree-exit, security-tripwires.
delivery-orchestration-dispatch-contract Main agent (plan-executor body) 6 [DISPATCH] 8 mandatory prompt slots, 4 pre-flight checks, parallel-escape conditions, collision check.
delivery-orchestration-closeout-schema Both — main reads, subagent emits 6 [INGEST] YAML schema for the dual-target atomic-write closeout (file before inline).
delivery-orchestration-replan-contract Main agent (plan-executor body) 6 [REPLAN] Firing signals, allowed/forbidden mutations, mandatory CHANGELOG audit, M=3 escalation bound.
The slice-contract is the load-bearing handshake between the two delivery skills. Plan-writer emits stories that pass the slice-contract validator the executor runs at pre-dispatch. Get this contract wrong on either side and the executor halts before the first slice ships.

5. Resumability invariants

Both stateful skills emit Position: [node-id] — <context> every turn. On context compaction the next turn re-reads:

  1. Skill state file (meta.yaml or equivalent) → which node was active
  2. Filesystem state (INDEX.md / STORIES.md / closeouts/) → where the work is
  3. Resume at the recorded node with no re-litigation

This is why the outer loop has to live in a main-agent skill, not a subagent — subagents have no Position to recover to.

6. The horizontal / per-module pipeline (alternate path)

When Stage 0 detects refactor / migration / single-module modernization (not vertical-slice-shaped), the orchestrator routes to the horizontal pipeline instead:

spec → architecture → /docs-design-writer → /docs-implementation-writer
     → /docs-test-plan-writer → /code-build-planner → (per-task subagent dispatch)

Same gates between stages, different decomposition grammar — horizontal/per-module rather than vertical/per-slice. The orchestrator picks one path or the other based on input shape; never both, never mixed. Mixing produces two parallel decompositions of the same code.

7. Two loops, one nest

Inner loop (Ralph / TDD) — lives in the subagent. Dispatch prompt carries the tdd-contract; subagent runs red → green → refactor up to the iteration cap. One slice, one subagent, one inner-loop run.

Outer loop (orchestration) — lives in the main agent. [PICK-NEXT-SLICE] → [DISPATCH] → [INGEST] → [REPLAN] across all slices in the manifest. Stateful, multi-turn, escalation-capable. Cannot move into a subagent — subagents are one-shot, can't ask the user, can't recover Position on compaction.
